# Findings on the Galaxus MCP endpoint (2026-11-11)

Notes from building and testing this skill against `https://mcp.galaxus.ch/`.

## What the skill does

Each call returns at most 50 results and there is no pagination. The skill
therefore splits the price range into smaller bands until each band fits in
50 results, and reports how complete the search was (for example "complete:
610 of 610 products, 32 calls"). It also reads specs such as RAM, Android
version and refresh rate from the product records. Calls are sequential with
a small delay and capped at 60 per search by default.

## First results

In a first eval round ([`evals/cases.md`](../evals/cases.md)):

- **With the skill:** searches came back complete for "Samsung smartphone" at
  CHF 200–500 and for 27-inch monitors at CHF 100–250 (in two runs).
- **Single plain call:** the same questions answered this way looked at 30–50
  products out of hundreds. One answer filled in RAM and Android versions from
  the model's general knowledge rather than from Galaxus data.

## What would help agents most

1. **Pagination or an offset.** This is the most important one. Splitting by
   price works, but it costs many calls.
2. **Decimal price bounds.** With whole francs only, more than 50 products at
   one price cannot be separated. "Redmi 17" matches about 290 phone cases at
   CHF 19–23, and three 1-franc bands hold 72–78 products each. The best an
   agent can honestly report there is "partial".
3. **Structured specs.** The `properties` string is useful, but RAM, OS
   version and refresh rate are often only in the free-text description, in
   five languages, and sometimes not there at all. Structured fields would
   remove a lot of guesswork.

   Example: a user on the announcement page reported finding an Android 17
   phone under CHF 300 on the site in two clicks, while their AI assistant
   said none existed. The site's "Android 17" filter lists 91 smartphones; the
   cheapest is the Samsung Galaxy A18 (128 GB, 4G, CHF 189, id 76242067). Its
   MCP record has `properties` `128 GB, Black, 6.70", Dual SIM, 4G` and an
   873-character description (en and de) that never mentions Android, One UI
   or an operating system. No agent can learn from the MCP data that it runs
   Android 17. This skill reports such phones as "unknown, could qualify"
   instead of "does not exist", but it cannot confirm them.
4. **Documented availability classes.** `_meta` returns `TICK`, `FULL`,
   `THREE_QUARTER`, `HALF`, `QUARTER` and `UNKNOWN`. Their meaning is not
   documented, so the skill shows them raw and labelled as undocumented.
5. **Clearer errors.** A one-character query returns `errorMessage` with
   `totalCount` 0, which a naive client would read as "no results".
6. **Usage terms.** No terms for automated use of the endpoint were found. A
   short note on acceptable request volume would help tool builders stay polite.

Searching by brand plus category within a price range works very well.
